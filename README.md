# FootPrint execution provenance demo

A reproducible, synthetic application example using **FootPrint.js** and **HCIFootprint**. It separates approval, dispatch, handler execution, settlement and observed application state.

Prepared by Sanjay Krishna Anbalagan in a personal capacity for review before possible technical outreach to the NIST NCCoE team. This is an independent project. No material has been sent to NIST; no NIST endorsement, affiliation or conformance is claimed.

## Run

Use **Node 22 or newer**:

```sh
cd example
npm ci --ignore-scripts --no-audit --no-fund
npm test
```

The locked dependencies are `footprintjs` **10.1.0**, `hcifootprint` **3.0.0**, and transitive `foottrace` **1.5.0**. The installation downloads the npm packages; the test itself runs locally. No model, agent, cloud account or API key is needed.

The test regenerates `evidence/` and exits nonzero if an assertion fails. Run it in a disposable copy if you want to preserve the captured review snapshot. Native timestamps and run IDs change between runs. The committed HTML and brief describe the captured run and are not regenerated by `npm test`.

## Nine targeted scenarios

The application updates a synthetic service request from **Open** to **Closed**. Approval is simulated by trusted host code; it is not a human-authentication test.

| Scenario | Observed result |
| --- | --- |
| No approval | Invocation refused; no handler entry |
| Caller supplies `confirm:true` | Refused without a recorded host decision |
| Approved input changed | `APPROVAL_MISMATCH`; no local change |
| Approved action changed | `APPROVAL_MISMATCH`; no local change |
| Correct approval used once | Handler returns; state becomes Closed with one new revision |
| Approval reused | `APPROVAL_SPENT`; no additional change |
| Handler returns without effect | Dispatch accepted, expected state absent, settlement refused |
| Failure after local write | Settlement refused while the application change remains |
| Direct application handler call | Local change occurs outside the session approval boundary |

**9/9 means nine expected scenario outcomes were reproduced**, including deliberate fault and coverage-limit cases. It does not mean nine comprehensive security controls passed.

## What the libraries and adapter do

**HCIFootprint** gates configured high-effect agent calls through its enforcing session. Single-use approvals are bound to action and input and are consumed when dispatch is accepted, before handler completion.

**FootPrint.js** records the managed orchestration and instrumented handler flows. The example-owned adapter correlates the native records and compares before/after application state. This joining/reporting logic is not a native combined feature of the libraries.

Two counterexamples are central. In the no-op case, `effectVerified:true` records reported write keys while `verifyHeld:false` reveals the absent expected value. In the failure-after-write case, a local change precedes a failure return that deliberately omits the session-state update; the application state changes while the session projection stays stale. A refused settlement does not establish rollback.

## Boundaries

Actor and approval labels are fixtures. A production host must authenticate people/callers, protect approval APIs and connect identity, delegation and policy decisions. Raw application calls and other unguarded routes remain host responsibilities.

The observations are in-memory, in the same process. The JSON records do not establish external database commits, independent observation, hidden model reasoning, complete route coverage, cryptographic authenticity, tamper-proof storage or formal verification.

`SHA256SUMS` identifies this repository's captured files for comparison; it is not a signature or execution attestation. From the repository root on macOS:

```sh
shasum -a 256 -c SHA256SUMS
```

The report separately hashes the exact executable and lockfile. Checksum files become stale after edits or reruns. `node_modules`, the unsent outreach draft and local QA artifacts are excluded.
